# Selective evidence expansion and gross-token safeguards

This follow-up targets avoidable follow-up research in compact adaptive MCP.
It does not establish native token savings. No evaluation, retrieval ranking
change, host integration or evaluator modification is included.

## Scoped behavior

When an automatic complete small-file bundle cannot fit, the existing same-finding
fallback may nominate the **first selected file only** as an optional complete
read. Both selected source units and every declared source identity must fit
before expansion. The primary file follows the existing evidence order: no new
ranking, model call, repository crawl or second lookup is introduced. Secondary
files do not expand merely to fill capacity. A nonfitting expansion is omitted,
never clipped.

This can restore a configuration assignment above a selected consumer function.
It does not prove semantic completeness, discover dependencies, or rescue a lookup
with no admitted passage. Two complete reads still have partial scope if the
finding cites four files. The original automatic-bundle guard remains: at most
eight declared files and 2,800 source characters. The fallback rechecks the same
finding, lifecycle, namespace and exact source identities. Current-file hashing,
whole-file secret scrubbing, line coordinates and caller-worktree verification
remain intact. Separate required units in one file cannot become overlapping
full-file reads; existing overlap handling preserves both cores.

Ordinary lookups, already-fitting bundles, explicit whole-file requests, generic
compact margins, legacy budgeted responses and no-budget interfaces retain their
selection behavior. There is no new tool or exposed request parameter.

## Repacking and Git pressure

Private selected-span coordinates support optional-first shedding during initial
packing. They are removed before public delivery. Later client/Git packing treats
the delivered span as required; it must not infer a smaller span or silently
discard evidence. If new framing exceeds the cap, the result fails closed. Tests
cover that pressure case and successful HTTP/client/Git/MCP delivery at sufficient
explicit caps. No new trusted span metadata is transmitted; optional shedding
after every wire boundary requires separately versioned forgery controls. The
earlier 1,983-byte non-Git diagnostic is not proof of Git fit at 2,048 bytes.

## Budgets are ceilings

`--context-budget` still defaults to 2,048 UTF-8 bytes. Only explicit
`--context-encoding o200k_base` counts encoding tokens. CLI help names both units.
No default, cap, negotiation, tokenizer requirement or retry policy changes.

The offline review found one four-file bundle fitting as evidence at 3,072 bytes,
whereas 4,096 permits extra saved prose. These are diagnostic examples, not optimal
settings. Existing options may be investigated under a separately authorized
comparison. Increasing a cap is not itself a token optimization. This patch's
salvage remains evidence-only and never restores saved prose during expansion.

## Publication and answer quality

Generated adaptive guidance and tool descriptions restrict publication to new
reusable findings from the requested task. A simple value lookup must not become
a procedure merely to justify a push. Explicit memory requests remain valid.
Unchanged reuse/restatements must not be republished; supporting identities must
be retained or dependent claims narrowed. The payload example and publication
exclusions remain.

All requested answer deliverables, examples, evidence, assumptions and necessary
research remain permitted. Publication failure, missing publication evidence and
abstention must not block the answer. No decision call, abstention report or
automatic retry is added. The policy clarifies that `limited` need not mean
insufficient evidence and that absence claims need scope coverage. Size guards
compare guidance/catalog bytes and pinned encoding counts against the prior head,
preserving its frozen policy strings. Those counts are not provider gross usage.

## Nonvalidated saved prose

Compact stale/unverified replies omit saved `content` and `content_truncated`, and
add `content_withheld` with the original status. Identity, source bindings,
lifecycle, age, taint, status and research/Git information are retained. The hit
is not reclassified as a miss or promoted to validated evidence. No source is
refreshed or trusted automatically. Legacy responses keep their saved content.
This additive display marker changes neither source schema nor identity bindings.

## Verification and boundaries

New regressions cover primary expansion over storage/HTTP/client/MCP, both
encodings, CRLF/LF and Unicode, Git verification, exact boundaries, later framing
pressure, same-file disjoint cores, no extra requests, unrestricted fallback
isolation, and stale/unverified display compatibility. Existing source drift,
permission, lifecycle, Git forgery, redaction, atomic unit, explicit-file and
publication-failure controls remain. Setup/stdio tests check policy delivery,
not agent obedience.

Retrieval admission, semantic query rewriting, dependency discovery, host routing,
source handles, batching, request accounting and evaluator changes remain separate.
No savings are inferred from fewer bytes or passing tests. Future acceptance must
retain all-attempt input-plus-output gross accounting over learning and reuse,
pinned main, informational No-Colony and every strict quality gate. Historical
protocols, logs, grades and conclusions are unchanged.
